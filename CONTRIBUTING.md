# Contributing

Thank you for your interest in contributing to **Good First Issue** 
Contributions of all kinds are welcome, especially those that help make the project more accessible to beginners.

---

## Quick Contribution Guide

If this is your first time contributing to an open-source project, follow these steps:

1. Fork this repository
2. Create a new branch from `master`
3. Make your changes
4. Run tests with `npm test`
5. Open a Pull Request with a clear description of what you changed

---

## Basics of Contributing

- Use clear and descriptive commit messages
- Run tests with `npm test` before submitting a Pull Request
- Fix any issues surfaced by the test suite before pushing your changes

### Example Commit Messages

- `docs: improve README clarity`
- `docs: add quick contribution guide`
- `test: improve CLI test coverage`
- `fix: handle empty GitHub API response`

---

## How You Can Contribute

There are several great ways to contribute to Good First Issue:

### Improving Documentation

Documentation lives primarily in [README.md](./README.md).  
If anything is unclear, outdated, or missing, documentation improvements are always welcome.

### Adding New Projects

If you'd like to add a new project, see the section  
[Adding New Projects](https://github.com/bnb/good-first-issue#adding-new-projects) in the README.

### Solidifying the Module

Although Good First Issue started as a CLI, it can also be used as a module.  
Contributions that improve the public interface or developer experience are highly appreciated.

### Enhancing Tests

- Tests are written using [Jest](https://www.npmjs.com/package/jest)
- Linting is handled by [Standard](https://www.npmjs.com/package/standard)

Improvements to test coverage and reliability are always welcome.
